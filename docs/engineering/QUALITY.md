## 建议统一验证入口

建议为实施项目建设 `scripts/verify.ps1 -Scope <范围>` 这样的统一入口，让本机与 CI 调用同一套检查。以下范围是一种组织方案，可按技术栈调整。

| 范围 | 检查内容 | 适用变化 |
| --- | --- | --- |
| Docs | 结构、索引、链接、当前事实边界、差异格式 | 文档与指令 |
| Harness | Docs、检查器回归、PowerShell 兼容、隔离仿真与范围选择 | 验证工具和执行机制 |
| DotNet | Docs、还原、Release 构建、后端测试 | 采集或中心代码 |
| Web | Docs、锁定依赖、构建、静态与浏览器回归 | Web 行为与依赖 |
| App | 后端与 Web 组合 | 跨端功能或嵌入式边缘页面 |
| All | Harness、后端、Web、本机数据库 API | 数据库与跨域影响 |

选择按行为影响，不按文件数量。测试过滤只在能证明覆盖直接影响时使用，共享持久化、并发或生命周期需要更全面证据。

## CI 选择与保守回退

CI 按变更清单选择范围；未知路径、无法可靠取得差异或取得不完整差异时回退 All。读取 Git 文件名显式关闭路径转义，避免中文路径被误分类。嵌入后端的边缘页面要选择覆盖后端与浏览器的范围。

CI 执行和托管平台强制分支门禁是不同能力，不能仅凭存在工作流就宣称失败变更绝不可能合并。

## 测试隔离

浏览器主回归显式模拟需要的 API，未匹配请求立即阻断。数据库与服务测试使用隔离实例、随机服务和临时数据。管理员权限不足的系统服务测试明确跳过；模拟结果不能替代真实服务管理器验证。

固定时区的业务样例要匹配测试环境。受调度和锁等待影响的测试避免无关并发噪声。检查失败必须传播非零退出码，测试框架本身的失败路径也有回归。

## 最大化窗口验收

前端修改前后用有界面、实际最大化的浏览器检查。记录实际视口、系统显示缩放、浏览器缩放与设备像素比；未知项明确写未知，不仅凭截图尺寸或 DPR 反推。

覆盖相关页面、控件组、正常与异常状态，查看原比例文字与控件。固定视口、无头回归和长截图是补充；没有真实窗口检查不能声称视觉验收完成。

## 性能证据

先定义收益、基线和不能退化的行为，再用可比较输入验证。选择相关的耗时、长尾、吞吐、CPU、分配、锁、积压或跳周期指标。功能通过不等于性能无退化，局部微基准不等于现场整轮采集。

## 知识生命周期

跨步骤任务才建立 active 计划；完成后将稳定契约合入产品、设计或工程文档，并在单独的结果目录中记录结论与证据。当前交接更新已有条目，不堆积历史。新增正式文档同步索引，引用采用稳定位置和锚点。

## 证据如何表达

实施时分别记录已执行、失败、跳过和未运行的检查，并说明环境与版本。设计评审关注契约，运行验证关注实际行为，二者不能互相替代。
