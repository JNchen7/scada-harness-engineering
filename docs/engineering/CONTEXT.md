# 任务路由与上下文工程

[工程索引](index.md)

## 简短入口承载什么

建议入口优先告诉代理：当前事实到哪里找、业务和设计分别由谁定义、什么动作禁止、选哪个验证入口。领域细节放入分类文档，不要求每次任务阅读整个知识库。

本仓库的 AGENTS.md 管理文档维护；实施应用时，可按此方法建立自己的任务路由和验证入口。

## 任务路由

| 用户任务 | 首读材料 | 有依据时继续查 |
| --- | --- | --- |
| 修复故障报表 | 报表口径、报警生命周期、数据库查询 | 分类入口、导出、迁移重跑与总览 |
| 修改缓存或停止 | 采集设计、安全门禁、质量要求 | 服务宿主、部署恢复、内存与磁盘保护 |
| 修改查询交互 | Web 公共契约、页面状态 | 共享查询作用域、同组页面与导出 |
| 扩展维保流程 | 维保状态、角色、组织和版本契约 | 照片、计划生成、审核与历史汇总 |
| 已授权运维 | 当前交接、目标与对应操作规程 | 候选、恢复条件与当次证据 |

从项目可查证的信息自行查证；真正影响结果或授权的未决问题才询问用户。这样减少用户重复描述，也避免把模型猜测当作需求。

## 单一事实来源

业务范围归产品规格，实现状态与接口归设计，执行规则归工程，当前对象、版本与授权归交接。成果账本和 Git 历史提供依据，不覆盖当前口径。

一个事实可以被多个地方引用，但不要维护多个可独立修改的副本。尤其不要把当前服务器地址、候选包和即时状态复制进架构文档。

## 冲突处理

例如，若第一阶段暂不做手机端，而第二阶段加入维保拍照，应标明各自适用范围；不能取第一个命中的文档就停止。字段、实现或测试与设计冲突时，先核对变更和已确认决定，再修正过时一侧。

规则来源与优先级必须明确。历史“本次允许重启”不能授权下一次重启，旧测试结果也不能为新配置背书。

## 交接替换机制

当前交接只保留接手必需的目标、有效材料、最近结论、未完成项、故障与授权。新结果替换旧条目，完成事项移出待办；稳定契约回写正式文档，完整过程留在历史和受控证据位置。

自动检查能发现缺入口、失效锚点和部分事实边界；是否重复、过时或误导接手仍要人工或代理审阅。不要把文件变短当作唯一目标，也不要为了“保留上下文”无限增长。
