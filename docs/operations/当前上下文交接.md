# 当前上下文交接设计

[运维索引](index.md) · [交接模板](../../templates/current-context.md)

我建议为需要长期接手的工作维护一份简短的当前交接。它回答“现在要做什么、哪些材料有效、哪些结论成立、下一步做什么”，减少代理从长聊天或旧记录中猜测状态。

## 接手所需的信息

| 问题 | 应维护的内容 |
| --- | --- |
| 当前目标是什么？ | 目标、范围、优先级 |
| 什么材料有效？ | 版本、候选、正式契约入口 |
| 什么已被验证？ | 对象、时间、环境与覆盖范围 |
| 什么仍未解决？ | 未完成项、有效失败原因与依赖 |
| 当前允许做什么？ | 对象、动作、条件和授权边界 |

## 维护规则

新结果替换旧条目，完成事项移出待办。稳定规则回写正式设计，过程与结果记录另存并由交接引用。无状态变化时无需追加工作报告。

## 常见反例

旧候选与新候选同时标为有效，会使代理选错版本；只写“测试通过”会遗漏对象；复制旧操作授权可能扩大范围；删掉失败原因却保留成功标题，会掩盖未解决状态。

## 如何验收交接质量

让另一位读者仅通过交接和链接定位下一步，确认他能区分规则、事实、推测与待验证事项。检查器可以发现失效链接，事实是否过时仍要审阅。

这份页面是维护方法说明。开始具体实施后，再用模板填写当次事实。
