# 中心服务发布与恢复

[运维索引](index.md)

建议将巡检、诊断、发布、服务重启和程序回退纳入受控入口，统一目标校验、状态记录和失败恢复。

## 发布前的事实

目标、当前版本、候选、数据库兼容性和允许影响必须一致。真实环境校验失败时不能为了继续流程降低连接校验或改用未确认目标。

## 就绪与存活

服务进程存在只是存活信号。业务就绪还依赖数据库可用、必需结构齐备、认证与关键 API 行为正常。首页 HTML 可以打开，不能证明数据库或登录流程可用。

## 分阶段操作

预检 → 记录与准备 → 停止与切换 → 启动 → 就绪与业务检查 → 完成或恢复。关键阶段保留证据，操作串行，避免两次发布相互覆盖。系统整机重启是单独授权的动作，不由普通发布需求推导。

## 回退与数据兼容

程序回退不等于数据库回滚。新结构或数据是否允许旧程序读取，需要单独审核。恢复旧程序后也需要验证服务路径、就绪和业务 API，不能把文件复制成功当作恢复成功。

回复丢失、连接中断或日志未完成时，先检查实际阶段与状态，不盲目从头重放。数据库不可用不能被页面加载成功掩盖。

## 脚本的工程可靠性

建议回归覆盖启动或停止过渡状态、路径不匹配、候选不就绪、恢复失败、迁移失败、错误目标与连接失败。Windows PowerShell 5.1 与较新 PowerShell 的外部进程参数行为不同，需要真实进程仿真，不只检查字符串拼接。

仿真只验证隔离模型中的行为；进程输出成功仍需对应的状态断言。真实服务验收应在明确授权的目标环境中单独安排。

## 运维知识维护

操作规程保留长期契约；当前交接保留当次目标、版本、有效授权与未完成恢复；原始日志留在受控证据位置。三者通过链接关联，避免多处维护同一动态事实。
