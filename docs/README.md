# 项目知识库

[首页](../README.md) · [快速阅读路线](portfolio/项目能力与阅读路线.md)

我建议把知识按职责分类：需求回答“为什么做”，设计回答“如何组织”，工程规则约束“怎样开发”，运维规划“怎样交付”，执行计划记录“怎样推进”，参考资料统一字段与示例。

| 分类 | 主要问题 | 入口 |
| --- | --- | --- |

| 设计文档 | 架构、采集、数据库、报警、Web 与维保 | [design-docs](design-docs/index.md) |

## 资料如何配合

建议将每条规则放在一个正式位置，其余页面引用它。产品范围以规格为准，接口和状态以设计为准，执行权限以当次授权为准，当前进度由交接记录维护。发生冲突时核对决定及适用阶段，不能简单采用搜索到的第一段文字。

这里的 [交接说明](operations/当前上下文交接.md) 展示维护方法；[任务卡](../templates/task-brief.md) 和 [决策记录](../templates/design-decision.md) 可以在具体实施时填写。整体定位见 [使用说明](方案定位与使用.md)。
