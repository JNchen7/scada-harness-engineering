# 设计能力与阅读路线

[作品集索引](index.md) · [首页](../../README.md)

这份方案展示我如何组织一个复杂软件问题：先厘清目标和约束，再连接系统组件、业务规则、AI 开发流程与验收标准。读者可以通过设计取舍与问题推演评价我的规划能力、全栈思考和 Harness Engineering 应用思路。

## 三分钟阅读

先读 [架构地图](../../ARCHITECTURE.md) 理解组件边界，再读 [Harness](../engineering/HARNESS.md) 理解 AI 应怎样进入开发流程。最后选一个问题推演，观察方案是否处理失败路径，以及怎样证明设计成立。

## 按岗位深入

- AI 辅助开发：入口路由 → 上下文维护 → 允许集 → 检查器负向回归 → 交接。
- 全栈开发：角色与组织 → 维保状态 → 后端事务 → 前端草稿与冲突 → 端到端验收。
- 后端与数据：稳定事件身份 → 可靠入箱 → 生命周期 → 区间归并 → 数据库迁移。
- 工程可靠性：本地落盘 → 确认重传 → 协作停止 → 版本切换 → 幂等恢复。

## 评审时可以追问

为什么选择这个边界？什么输入会使简单方案失效？替代方案的成本是什么？AI 应自主处理哪些细节？如何发现它偏离了业务规则？怎样区分设计成立与运行验证完成？
