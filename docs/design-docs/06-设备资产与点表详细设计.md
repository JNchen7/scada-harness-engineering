# 设备资产与点表详细设计

[设计索引](index.md) · [字段样例](../references/点表字段与数据字典.md)

## 核心模型

| 实体 | 主责 | 关键约束 |
| --- | --- | --- |
| equipment | 设备身份、组织路径、启用与心跳摘要 | 设备编码稳定，显示名称可变化 |
| protocol_connections | 协议与连接定义 | 当前设备只采用已定义的有效连接契约 |
| points | 地址、名称、类型、周期及分类 | 设备编码与地址共同定位点位 |

点表中的显示名称不能替代协议地址；真实地址也不应被程序为了“清洗”而静默改写。导入前就应形成已审核的地址语义。

## 两种开关不能混淆

`collector_enabled` 决定点是否进入本次采集配置。`is_excluded_from_fault` 决定报警是否参与故障统计。停采、排除统计、删除点位是三件不同的事情。

中心保留全部点定义，生成配置时只下发启用点。网关接收已经筛选的点集，不再维护另一套开关解释。希望保留历史关联的停采点应留在完整点表中。

## 完整集导入

工作簿代表一台设备的完整点集快照，而非增量补丁。预检需要报告新增、修改、删除、启停与总点数；缺少启用列或值非法不能默认为开启。

版本激活时，在一个事务内同步设备、协议与点位。相同设备和地址的既有故障分类保留服务器当前值，不由导入快照覆盖；新增点采用明确默认。这样可避免部署点表时重置运营人员已经维护的统计分类。

## 错误处理与验收

重复地址、不支持的数据类型、周期错误、缺失必填列应在远程动作前失败。批量分类修改先验证全部目标，任一目标不存在或不是报警点则整体拒绝。

验收同时检查数据库、配置生成、网关配置校验器与页面计数，不能只测 Excel 能否打开。AI 修改字段时需要同步这些消费者，而不是仅更新数据库列。
