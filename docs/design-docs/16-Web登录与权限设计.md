# Web 登录、会话与权限设计

[设计索引](index.md) · [业务角色](../product-specs/08-用户角色与操作记录详细设计.md)

## 会话边界

中心 Web 使用框架内置 Cookie 认证，写请求配合防伪校验，页面和接口分别验证权限。采集上传与独立边缘页面有各自的接入边界，不能因中心 Web 登录存在就宣称所有设备接口都被同一认证保护。

公开文档不包含账号、初始口令、密钥或连接配置。会话细节属于项目实现选择，不作为通用安全产品推荐。

## 会话更新与状态隔离

建议不要让后台轮询无限延长会话；可见页面上的真实用户活动按受限频率触发续期。重连不自动等于续期。退出和切换账号卸载旧工作区，取消或失效旧请求，避免跨账号显示迟到结果。

身份探测和防伪令牌读取要有超时，且覆盖响应体读取。服务连接错误与未登录分开处理：连接恢复后重新核对身份，再进入工作区或登录页。

## 权限检查的位置

| 操作 | 需要核对 |
| --- | --- |
| 页面进入 | 查看权限 |
| 修改分类或规则 | 相应查看与操作权限、防伪校验 |
| 网关导入并部署 | 配置维护和远程操作权限共同成立 |
| 导出 | 对应明细权限，不能仅凭总览权限 |
| 公共配置摘要 | 按请求用途裁剪字段，不一律返回完整协议和点表 |
| 维保签名 | 业务级别、组织归属、操作权限与禁止自审 |

前端导航和按钮只是交互提示，服务器是权限判定的执行位置。权限变更后，列表、详情、写操作、照片和导出要一致。

## 用户管理体验

账号列表、业务身份、负责组织与操作权限应能快速区分。编辑草稿与列表刷新分别维护；组织加载失败时不能保存不完整授权。保存和删除防重入，返回保留筛选与滚动，确认取消和键盘焦点有清晰结果。

## 回归重点

无登录、缺少防伪、只读用户写入、权限撤销、管理员自审、跨组织照片读取、退出后迟到响应、服务不可达与恢复都需要验证。设计上的允许集不能由前端控件值直接替代。
