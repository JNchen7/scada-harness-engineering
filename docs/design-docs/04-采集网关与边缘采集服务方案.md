# 采集网关与边缘服务方案

[设计索引](index.md)

## 业务接入约束

设备网络与业务网络可能隔离，不同设备可能使用重复的内部地址。建议由边缘节点承担设备侧读取，再向中心上传业务数据。拓扑、路由与硬件应根据现场隔离条件和容量预算确定。

该选择不意味着允许透明桥接网络，也不意味着中心浏览器一定能访问设备侧。采集上行、远程管理和边缘实时页面是三种访问路径，部署时分别验收。

## 边缘节点职责

| 责任 | 必要状态 |
| --- | --- |
| 配置加载 | 当前有效版本、加载失败原因、可用恢复配置 |
| 协议采集 | 最近成功时间、分组异常、周期滞后 |
| 本地保存 | 待落盘批次、写入错误、容量保护状态 |
| 补传 | 各类待上传量、最老业务时间、最近成功接收 |
| 心跳 | 采集状态、配置版本、程序标识与资源摘要 |

健康不能只用“进程还在”判断。服务运行、PLC 可读、缓存可写和中心可达分别观察；缓存保护暂停不能被显示为正常采集。

## 当前与历史分离

实时快照服务现场查看，中心只保存应上传的历史与事件。快照刷新频率、协议采集周期和上传节奏分别设计，避免界面要求带来全量中心写入。

## 时钟与恢复

业务事件保留发生时刻及偏移信息，中心按约定时间口径保存和查询。调度用单调时钟，不能用墙钟跳变改变扫描节奏。部署验收使用中心递增的心跳修订号判断“新心跳”，避免依赖两台主机的时钟相等。

## 接入验收

先验证配置和隔离模拟，再按授权检查设备协议、原系统通讯是否受影响、完整扫描时间、断网补传与恢复。不把读取一个点成功当作整套采集链路已通过，也不将某一配置的历史验收覆盖到后来新增点位。
