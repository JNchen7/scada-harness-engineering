# Web 页面与查询状态设计

[设计索引](index.md)

## 信息架构

采集监控覆盖设备总览、当前报警、历史报警、趋势和故障报表；配置诊断覆盖设备、协议、点位、心跳、日志和网关维护；设备维保覆盖工作台、巡检、保养、标准与计划；用户管理与业务权限分开显示。

界面按用户任务组织，而不是直接把数据库表暴露成菜单。建议按使用场景选择桌面信息密度和手机维保布局；主题应共享语义与状态颜色，避免每个页面各自定义规则。

## 查询至少有这些状态

| 状态 | 页面行为 |
| --- | --- |
| 尚未满足条件 | 引导选择设备或点位，不显示“查询无数据” |
| 条件已编辑但未应用 | 标明待查询，禁止沿旧条件翻页或导出 |
| 正在查询 | 禁止重复操作，保留需要保留的旧结果 |
| 成功且有数据 | 同步记录已应用条件、页码和快照 |
| 成功但为空 | 说明当前条件没有结果 |
| 失败且有旧数据 | 标为上次结果，保留其上下文 |
| 失败且无旧数据 | 显示错误与重试，不冒充正常空态 |

输入控件里的“正在编辑条件”与当前列表的“已成功查询条件”分别维护。迟到响应不能覆盖较新的查询，退出、切页与切换账号要失效旧请求作用域。

## 分页与导出的一致性

历史报警以服务器分页返回真实总数与页数，筛选在分页前执行。趋势固定首查询的 ID 上界，曲线、表格与当前页导出一致。页大小、筛选、重新查询如何重置页码和快照，需要分别定义。

历史报警导出读取全部匹配结果，任何一页失败都不下载部分文件；趋势导出明确只包含当前页。整数 ID 上界作为字符串传递，避免浏览器整数精度损失。

## 同类入口与共享行为

趋势图上方和明细底部的翻页入口共用状态。输入回车查询与候选选择回车不能冲突。查询、加载、失败、无数据、待应用状态在同组页面一致。共享控件修改需要检查实际调用方，而不是仅检查当前截图。

## 实际使用路径

前端修改先看用户日常的最大化窗口，再在相同条件下检查首屏、滚动、表格、弹窗、键盘焦点和失败恢复。固定视口回归是补充，不能冒充最大化验收。手机维保还需摄像头、触摸和真实网络条件的单独验收。

## AI 协作中的具体价值

把这些状态写成契约，代理才能在修改分页、筛选或保存时主动核对相关入口。浏览器自动化必须模拟必要 API，遗漏请求立即失败，避免测试误连本机实际服务。相应门禁见 [QUALITY](../engineering/QUALITY.md)。
