# 执行计划应该怎样管理

[知识库](../../README.md) · [问题推演](../examples/index.md)

建议只为跨步骤、跨组件或需要交接的任务建立 active 计划。任务卡保存目标、范围、约束、关键决定、验证与阻塞；完成后将稳定规则写回正式设计，并保存结果记录。

## 一张计划卡应包含什么

| 项目 | 建议内容 |
| --- | --- |
| 目标 | 用户完成什么流程，哪些行为必须保持 |
| 范围 | 直接影响的组件、状态与同类入口 |
| 决定 | 已选方案、理由、代价与尚未确定事项 |
| 步骤 | 每步的输入、产物、依赖和检查点 |
| 验收 | 正常与异常路径、运行环境和证据 |
| 交接 | 当前进度、有效材料、阻塞及下一步 |

## 示例：增加维保照片

先确定照片与任务修订的关系，再设计接入权限、上传会话、失败重试、资源释放和引用校验。拆分为数据契约、后端接口、手机交互和验收四部分；桌面模拟通过后，仍需独立验证手机摄像头与网络行为。

## 计划结束条件

验收项有明确结果，未覆盖项说明影响，稳定契约已更新，交接足以让下一次任务接续。不要把已完成步骤长期留作待办，也不要用“代码已生成”替代用户结果。

使用 [任务卡](../../../templates/task-brief.md) 和 [交接模板](../../../templates/current-context.md) 填写具体事实。本文展示计划管理方法，不包含正在执行的应用任务。
