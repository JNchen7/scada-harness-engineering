# 问题推演：设备维保如何形成业务闭环

[问题索引](index.md) · [完整设计](../../design-docs/19-设备维保无纸化.md)

假设要将巡检与保养搬到 Web 和手机端，怎样处理标准变化、责任确认、并发和弱网？下面给出拆解建议。

## 从“把表搬到网页”开始的问题

只有输入框和保存接口不能满足责任追溯：标准会变、多人可能领取同一任务、用户可能重复提交、手机可能断网、同名组织可能跨线、审核者可能恰好就是执行者。

## 业务拆解

标准及版本、设备计划、周期任务、修订、命令、操作事件和照片分别承担职责。生成任务保存当时标准和组织快照；当前规则变化不改历史责任。

| 现实问题 | 设计回应 |
| --- | --- |
| 两人同时领取 | 事务与领域锁，明确唯一领取人 |
| 保存成功但响应丢失 | 原 requestId 重试，内容一致性检查 |
| 老页面覆盖新修改 | version 检查，冲突需核对 |
| 有管理员权限但不能自审 | 系统身份与业务签名分开 |
| 组织权限撤销 | 列表、详情、照片、导出与操作同步收回 |
| 标准后来修改 | 旧任务和汇总保留生成时快照 |
| 断网 | 本机草稿隔离保存，不伪造正式提交 |
| 拿旧修订照片重复提交 | 照片会话绑定本次任务修订 |

## 前后端一起验收

服务器拒绝非法状态和权限，浏览器明确待保存、冲突、断网、失败和重试。前端不能只靠按钮禁用保护并发，后端也不能把错误丢给用户自行理解。

查询默认日期、时间预设、分页和导出在多菜单间一致；迟到响应不能覆盖新查询。照片资源在关闭、切页与离开前台时释放，权限拒绝时有可理解提示。

## 组织模型变化时怎样处理

如果把归属从细粒度工序提升为阶段授权，再动态展开工序，就需要同步迁移、账号保存、任务权限和查询。迁移重复执行不能把已撤销的旧归属恢复回来。

## 展示的 AI 能力

把业务规则转成状态、事务和验收矩阵；让 AI 检查跨层消费者并完成关联修改；用隔离回归检验幂等、冲突和权限，而不是只验证表单能提交。业务确认与拍摄会话分别提供责任和流程证据，不能被当作自动决策或硬件防伪能力。
