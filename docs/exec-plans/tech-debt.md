# 技术债与工程边界

[知识库](../README.md)

只将有证据、影响和处理时机的问题写成技术债；未来愿景、通用化想法和可选整理不自动成为欠账。以下列出本方案实施时值得观察的风险和重审条件，并不预设每一项都已经成为技术债。

| 边界 | 为什么重要 | 何时处理或重新评估 |
| --- | --- | --- |
| CI 执行与强制合并门禁不同 | 工作流存在不能保证所有变更都被平台阻止 | 协作人数、自动发布或审计要求变化时核对托管规则 |
| 本机模拟不能覆盖实际系统与设备 | 真实服务、磁盘、网络和协议行为有额外条件 | 新运行路径进入现场前安排对应验收 |
| 动态统计有查询成本 | 规则即时生效不等于无限规模下稳定低延迟 | 实测数据证明瓶颈后评估索引、缓存或物化 |
| 长期保留需要容量与恢复管理 | 不删除并不意味着无限空间或已有备份 | 按数据增长和恢复目标安排保护措施 |
| 文档与实际状态可能漂移 | 自动链接检查发现不了所有语义冲突 | 相关任务交付时同步契约与当前事实 |

每条实际待办还应指定负责人、证据位置、处理时机和验证方式。不能通过一句“后续优化”把已知影响从交付说明中隐藏。
