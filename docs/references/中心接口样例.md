# 中心接口契约样例

[参考索引](index.md)

以下使用虚构设备、点位和时间说明接口契约，重点是身份、时间、确认和重试语义。

## 按数据类型分开接收

| 接口类别 | 目的 | 关键语义 |
| --- | --- | --- |
| runtime-data | 普通参数变化与快照 | 同类值批量入库 |
| runtime-100ms-data | 高频点历史 | 高频预算独立，仍按确认契约处理 |
| setpoint-data | 设定值变化 | 与普通参数分别保存 |
| equipment-status | 状态变化 | 不是每次扫描都写一条 |
| alarm-events | 原始开始、恢复事件 | 可靠入箱，不在请求内处理最终生命周期 |
| heartbeat | 版本、采集状态与资源摘要 | 在线、版本匹配和有效采集分别判断 |

## 一个值样本

| 字段 | 虚构值 | 契约 |
| --- | --- | --- |
| equipment_code | DEMO-001 | 稳定设备身份 |
| address | Demo.ProcessValue | 示例协议地址，不对应真实设备 |
| point_name | 示例过程值 | 显示名称 |
| value | 12.5 | 有效业务观测，非有限值不伪造 |
| collected_at | 2026-01-01 09:00:00 +08:00 | 采集观测时间 |
| uploaded_at | 2026-01-01 09:00:05 +08:00 | 本批上送时间，不替代采集时间 |

## 一个报警跃迁

| 字段 | 示例语义 |
| --- | --- |
| event_id | 首次创建后保持不变的事件标识 |
| equipment_code / address | DEMO-001 / Demo.AlarmA |
| event_status | active 或 recovered |
| event_time | 识别跃迁的业务时间 |
| operation_mode | 开始时自动、手动或未知 |
| description | 开始事件对应的描述快照 |

开始与恢复是两个独立原始事件，各有自己的稳定标识；同一事件的重传不能换标识。最终生命周期保存开始快照，恢复不会覆盖它。

## 错误与重试

输入错误明确拒绝，不能静默截断；重复已接收数据按幂等成功处理；超时和不明确确认保留本地批次；部分或不可解释响应不能被当作完整确认。数据库幂等、请求幂等与业务状态幂等需要分别设计。

字段定义见 [数据字典](点表字段与数据字典.md)，实现语义见 [报警设计](../design-docs/11-报警事件详细设计.md)。
